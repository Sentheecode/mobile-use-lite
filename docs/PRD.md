## 1. 背景

### 1.1 调研结论（必须保留）

用户研究了**阿里云 Qwen Intelligence Mobile-Use Agent API**：

- 形态：商业云 API。
- 输入：截图 + 任务描述等。
- 输出：SSE 流式返回 `tool_calls`（结构化工具调用）。
- **真机执行不在云端，在调用方。**

因此「Mobile-Use」本质是：**云端 VL/规划 + 调用方 harness**。本项目做**简版自研**：推理可用本地或自选 API（优先 oc + 免费 DeepSeek），执行层自研，不把商业 Mobile-Use 当作运行时依赖。

### 1.2 为何做 Lite

- 验证「截图闭环」是否值得投入，而不先买云额度。
- 动作 schema 与 harness 自有，便于以后换模型后端。
- 编码成本可控（oc + 免费档）；协作面预留 Origin，**不主动开 Cloud Agent**。

### 1.3 约束（硬）

- **项圈 1.0 主线优先**；本项目旁线，不抢人力/GPU/注意力窗口。
- 第一版全自动优先 **Android + ADB**；iOS 不做控整机。
- 敏感操作一律人确认。

## 2. 目标与非目标

### 2.1 目标

1. 实现可演示的 Agent 闭环：截图 → VL 分析 → 结构化动作 → harness 执行 → 新截图。
2. 最小动作集：`click` / `swipe` / `type` / `back` / `wait` / `done`。
3. 坐标约定：模型侧 **0–999 归一化**，执行前换算像素。
4. P0 mock 可演示；P1 真机短任务可复现。
5. 敏感 UI（支付 / 验证码 / 登录）触发 **Sensitive gate**，暂停等人。

### 2.2 非目标

| ID | 非目标 |
|----|--------|
| NG-1 | 不封装阿里云 Mobile-Use 为默认运行时 |
| NG-2 | 不做 iOS 全机自动化 / 越狱方案 |
| NG-3 | 不做跨 App 长规划、DeepLink 编排（P3 以后再议） |
| NG-4 | 不主动开 Cursor Cloud Agent |
| NG-5 | 不与项圈 1.0 争排期或共用「必须立刻修」的事故通道 |
| NG-6 | 本阶段不写业务代码、不建远程仓库 |

## 3. 用户与场景

### 3.1 用户

| 角色 | 描述 |
|------|------|
| 操作者（Senthee） | 发起任务、确认敏感步、验收短路径剧本 |
| 执行者（未来） | 按 PRD/phases 实现 mock → ADB；日常用 oc |
| 旁观者（可选） | Origin 协作评审；无 Cloud Agent 默认值 |

### 3.2 核心场景

| 场景 ID | 描述 | 阶段 |
|---------|------|------|
| SC-1 | 假截图序列上跑通动作合法性与会话状态机 | P0 |
| SC-2 | Android：打开指定 App，完成 3–8 步短路径（如进某页再返回） | P1 |
| SC-3 | 遇到登录/支付样例屏 → 暂停，人确认后再继续或中止 | P0 起约定，P1 实机验证 |
| SC-4 | iPhone：本地小 VL 看图给出建议动作，人点确认（不自动点系统） | P2 可选 |

### 3.3 反场景（不做）

- 自动完成支付、自动填短信验证码、自动登录第三方账号。
- 跨多个无关 App 的长程规划。
- 依赖商业 Mobile-Use SSE 才能跑通主路径。

## 4. 功能需求

### 4.1 Agent 环与会话

| ID | 需求 | 优先级 |
|----|------|--------|
| FR-01 | 系统支持多轮会话：每轮输入含任务目标、可选历史、当前截图元数据 | P0 |
| FR-02 | 每轮输出零个或多个结构化动作；结束动作为 `done` 或错误终止 | P0 |
| FR-03 | 会话状态可查询：running / waiting_human / succeeded / failed / cancelled | P0 |
| FR-04 | 支持人工确认后续轮（Sensitive gate 解除后继续） | P0 |

### 4.2 动作与坐标

| ID | 需求 | 优先级 |
|----|------|--------|
| FR-10 | 支持动作类型：`click`, `swipe`, `type`, `back`, `wait`, `done` | P0 |
| FR-11 | `click`/`swipe` 坐标为 0–999 归一化；driver 负责换算像素 | P0 |
| FR-12 | `type` 仅明文可打印输入；密码框场景必须走 Sensitive gate | P0 |
| FR-13 | `wait` 带超时毫秒；超时不崩溃，记入轮次结果 | P0 |
| FR-14 | 未知动作类型 → 明确错误码，不静默忽略 | P0 |

### 4.3 Driver / Harness

| ID | 需求 | 优先级 |
|----|------|--------|
| FR-20 | Mock driver：按剧本返回下一张假截图与执行结果 | P0 |
| FR-21 | ADB driver：截图、点击、滑动、输入、返回键 | P1 |
| FR-22 | Driver 接口统一，切换 mock/ADB 不改 Agent 环协议 | P0 |
| FR-23 | 执行后必须拿到新截图（或明确截图失败错误）再进入下一推理 | P0 |

### 4.4 安全与敏感

| ID | 需求 | 优先级 |
|----|------|--------|
| FR-30 | 检测到支付 / 验证码 / 登录相关意图或 UI 启发式 → `waiting_human` | P0 |
| FR-31 | 人未确认前，禁止下发 click/type 到敏感控件 | P0 |
| FR-32 | 确认与拒绝均写入会话审计字段（时间、操作者标记） | P1 |

### 4.5 模型后端

| ID | 需求 | 优先级 |
|----|------|--------|
| FR-40 | 推理后端可配置；默认路径面向 oc 工作流 + DeepSeek（或兼容 OpenAI-like API） | P0 |
| FR-41 | 可选：输出兼容「类 OpenAI tool_calls / SSE」便于以后对照商业 API（非必须运行时） | P1 |
| FR-42 | P2：iOS 本地 2B–4B VL 仅产出「建议动作」，默认不直连系统点击 | P2 |

### 4.6 工程与协作（产品约束型 FR）

| ID | 需求 | 优先级 |
|----|------|--------|
| FR-50 | 文档与日后代码目录建议见 architecture；本阶段只落文档 | P0 |
| FR-51 | 默认不开 Cloud Agent；Origin 挂载为可选后续 | P0 |

## 5. 非功能需求

### 5.1 性能

| ID | 要求 |
|----|------|
| NFR-01 | P0 mock：单轮（推理用桩时可）从「入截图」到「出动作」应可本地秒级完成演示 |
| NFR-02 | P1 ADB：短路径剧本端到端建议 &lt; 3 分钟（含人工确认则另计） |
| NFR-03 | 单会话默认最大轮次可配置（建议默认 20），防死循环 |

### 5.2 安全与隐私

| ID | 要求 |
|----|------|
| NFR-10 | 截图默认存本地工作区；不默认上传第三方（除非用户显式配置的模型 API） |
| NFR-11 | 日志默认脱敏：不记录完整密码、验证码正文 |
| NFR-12 | 敏感 gate 不可被配置项一键全局关闭（若将来加「开发者模式」须单独文档修订） |

### 5.3 可靠性

| ID | 要求 |
|----|------|
| NFR-20 | Driver 失败返回结构化错误，会话进入 failed 或可重试态，不裸崩 |
| NFR-21 | 模型返回非法 JSON → 可重试有限次，仍失败则 failed + 错误码 |

### 5.4 可维护性

| ID | 要求 |
|----|------|
| NFR-30 | 动作 schema 单源定义（日后代码与 api.md 一致） |
| NFR-31 | mock 剧本与真机剧本格式尽量同源，降低 P0→P1 摩擦 |

## 6. 验收标准

### 6.1 P0 验收

- [ ] 存在完整设计文档集（本 PRD + architecture + services + api + phases + risks + README）。
- [ ] 动作 schema 在 api.md 有 JSON 示例，覆盖全部六类动作。
- [ ] （开工后）mock 闭环：给定剧本，会话能 `succeeded`（`done`）或按错误码 `failed`。
- [ ] Sensitive gate：注入「登录/支付」假屏时进入 `waiting_human`，未确认不下发执行。

### 6.2 P1 验收

- [ ] 至少一条 Android 短路径剧本书面写明步骤与期望界面。
- [ ] ADB 实机跑通该剧本（可含人工确认步）。
- [ ] 坐标换算在目标分辨率上点击偏差可接受（人工目视点中目标控件）。

### 6.3 P2 验收（可选）

- [ ] iPhone 本地小 VL 对样例截图产出可读建议；执行需人确认。
- [ ] 不宣称「控整机全自动」。

### 6.4 产品级红线

- 任何演示若自动完成支付/验证码，视为验收失败。

## 8. 术语表

| 术语 | 定义 |
|------|------|
| Mobile-Use（商业） | 阿里云 Qwen Intelligence Mobile-Use Agent API：云端 SSE + tool_calls，执行在调用方 |
| Mobile-Use Lite | 本项目：自研闭环简版 |

| Sensitive gate | 敏感操作暂停并等人确认的会话闸门 |
| oc / OpenCode | 优先编码环境 |
| Origin | Cursor Origin，可选挂载远程协作，非本阶段必做 |
| Cloud Agent | Cursor Cloud Agent；默认不开 |
| 项圈 1.0 | 用户主线产品；本 PRD 约束旁线不得抢优 |
